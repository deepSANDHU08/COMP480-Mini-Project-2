COMP480 Mini Project 2 — Prolog Knowledge-Base and Reasoning System

Project objectives

The objective of this project is to build three small but complete reasoning systems in SWI-Prolog. Each system stores domain facts and applies logical rules to answer queries that are not explicitly stored. Together, the domains demonstrate direct and indirect inference, recursive search, list processing, Prolog unification and backtracking, constraint-style puzzles, and arithmetic represented by successor numerals.

Implementation overview

Transportation Network. Models illustrative British Columbia city connections and distances. It supports direct connection checks, reachability, cycle-safe route generation, route-distance calculation, shortest-route selection, and planning a multi-stop route under a distance limit.

Library Management. Stores fifteen books with authors, genres, publication years, members, and borrowing records. It identifies available and borrowed books, searches authors and genres, recommends books based on prior borrowing, traverses a genre-category graph, and allocates distinct books to readers with genre preferences.

Game World Adventure. Stores locations, map links, inventories, quests, quest prerequisites, and completed quests. It searches the world map safely, checks player possessions, verifies recursive quest dependencies, identifies available quests, and generates distinct item assignments.

Main functions

reachable/2, can_reach/2, route/3, and path/3 use a visited list. Their base case succeeds when the current location is the destination; their recursive case selects an unvisited neighbour. This prevents infinite loops in bidirectional graphs. route_distance/2 recursively adds edge distances, and shortest_route/4 selects the least-distance simple route.

In the library, available/1, borrower_of/2, recommend_book/2, and genre_path/3 derive catalogue information. In the game world, has_item/2, dependencies_met/2, and can_complete_quest/2 combine inventory and dependency facts. All domains include duplicate removal and successor-numeral values such as s(s(0)). Allocation predicates leave variables unbound so Prolog backtracking can enumerate valid solutions.

Challenges and solutions

Bidirectional links create cycles, so unrestricted recursive traversal could fail to terminate. Each traversal tracks previously visited nodes and only visits new ones; generated routes are therefore simple. The domains are independently runnable and use small local utility files instead of advanced external libraries. Automated suites test normal and failed cases, recursive inference, duplicate handling, puzzles, and successor arithmetic.
